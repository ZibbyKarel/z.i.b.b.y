01 — OPERATING MODEL

From subsystem orbs to a company

HIERARCHYYou are the CEO and appear only in the header. ZIBBY is the COO: the root node on the ORG map, with 11 departments under it.
NAMINGUI uses corporate names only. The old mythological names (Forge, Puls…) stay in code.
AGENTSAgents live in a shared pool (Architect, Coder, Reviewer…). Departments borrow them per subtask.
TASKA task is a parent. Each department it passes through runs its own subtask.
CHAINA chain is a fixed route across departments, defined globally in WORK. When a task has no chain, the COO classifier picks one and you can override it.
PIPELINEA pipeline is a fixed flow inside one department and is defined in that department. Rework loops (Review → Coder) exist only here.
HANDOFFGate rules decide whether a handoff between departments runs automatically or waits in NEEDS YOU.
ENTRYTasks enter three ways: COO chat or form, directly into a department, or inbound Slack/e-mail/Jira/GitHub through Monitoring.

WORKING ← running THINKING BLOCKED ← waiting ERROR DONE ← report IDLE
