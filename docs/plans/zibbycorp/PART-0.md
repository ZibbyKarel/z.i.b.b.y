## ZC-01 — Contracts: `departments` replaces `subsystems`

**Paths:**
- `libs/contracts/src/subsystems/**` is moved (`git mv`) to
  `libs/contracts/src/departments/**`.
- `libs/contracts/src/index.ts`.
- `libs/contracts/src/app.contract.ts`.
- Every contract schema that references a subsystem:
  - `agents`, `pipelines`, `approvals`, `memory`, `handoff`, `tasks`, `gates`, `activity`;
  - `automations`, `self-knowledge`, `herald` → `comms`, `maestro` → `release`.

**Deliverables**

1. `departments/department.schema.ts`:
   - `DepartmentIdSchema = z.enum(["dev","ops","sec","rel","inc","rnd","com","qa","knw","fin","per"])`,
     in the canonical org-chart order from the D-004 table.
   - `DEPARTMENTS: readonly Department[]` with fields:
     - `id`;
     - `code` (`"DEV"`);
     - `name` (`"Development"`);
     - `tagline`;
     - `mandate` (carried over from today's registry, persona wording removed);
     - `integrationKinds` (D-011; e.g. `com: ["slack","email","calendar"]`,
       `ops: ["github"]`, `sec: []`…; copy today's channel/monitor routing);
     - `tierDefault` (ex-`SUBSYSTEM_TIER_DEFAULT`; `inc` = ask as `beacon` was).
   - The **`color` field is dropped**. Departments are monochrome in the new design; state
     is the only colour. Remove its web consumers in ZC-04.
2. `departments/legacy.ts`, **the only file allowed to contain persona ids**:
   - `LEGACY_SUBSYSTEM_ID_MAP: Record<string, DepartmentId>`.
   - `normalizeDepartmentId(v: unknown)`.
   - `withLegacyDepartmentField<T>(schema)`, a `z.preprocess` that:
     - copies `ownerSubsystem` → `department` and `subsystem` → `department` when the
       new key is absent;
     - maps old ids.
   - Unit test: every old id maps, and unknown ids pass through so the enum can reject
     them.
3. `DepartmentIdSchema` itself accepts legacy ids: `z.preprocess(normalizeDepartmentId, enum)`.
   This covers ids embedded anywhere: handoff rules, targets, approvals, activity.
4. Field renames per D-004, wrapped with `withLegacyDepartmentField` on every **stored**
   entity schema:
   - Agent, Pipeline, Approval, Note/memory frontmatter, HandoffRule, HandoffSignal,
     ScheduledTask target, GateRule scope (if it has one).
   - `Agent.department` and `Pipeline.department` are **required**, as `ownerSubsystem` is
     today (422 without it).
5. `TaskTargetSchema`:
   - member `kind: "subsystem"` → `kind: "department"`;
   - a preprocess maps a stored `{kind:"subsystem", id:"forge"}` → `{kind:"department", id:"dev"}`.
6. Router `departments.contract.ts`:
   - `/api/departments`;
   - `/api/departments/:id/roster`;
   - `/api/departments/unowned` → rename to `/api/departments/unassigned`.
   - Findings and seen endpoints are renamed likewise.
   - The old `/api/subsystems/*` paths are **not** kept. Web and API change in the same
     part and there are no external clients.
7. Persona-named contract dirs:
   - `herald/` → `comms/`, `maestro/` → `release/`;
   - `subsystem-findings` → `department-findings`.
8. Contract tests are renamed and updated. Add a test that asserts a legacy payload parses
   for each stored schema.

**Invariants:**
- No behaviour change.
- Ids are renamed, not remapped semantically: `beacon`'s ask default stays on `inc`.

**Verification:**
- `tsc -p libs/contracts`, exit 0.
- `pnpm exec vitest run libs/contracts`.

**Commit:** `refactor(contracts)!: subsystem → department (ids dev/ops/sec/…)`

## ZC-02 — API rename

**Paths:**

| Before | After |
|---|---|
| `apps/api/src/subsystems/**` | `apps/api/src/departments/**` |
| `sentinel/` | `security-scan/` |
| `maestro/` | `release/` |
| `herald/` | `comms/` |
| `loom/` | `arch-audit/` |

Plus every API file that uses the renamed symbols:
- tasks classifier and scheduler;
- handoff, gates, agents, pipelines, memory, automations, activity;
- briefing, channels, self-knowledge, agent-factory;
- `app.module.ts`;
- `tools/docs-sync/manifest.mjs` and `docs/api/*`.

**Deliverables**

1. Module, class and file renames:
   - `SubsystemsService` → `DepartmentsService`;
   - `SubsystemFindingsStore` → `DepartmentFindingsStore`;
   - `subsystem-seen.store` → `department-seen.store`, whose data file is
     `department-seen.json`. It reads the legacy file if the new one is absent.
   - `owner-backfill` / `owner-seed` → `department-backfill` / `department-seed`.
   - `SentinelService` → `SecurityScanService`, and likewise for the other three.
2. `SUBSYSTEM_FALLBACK` → `DEPARTMENT_FALLBACK`. The classifier stage-1 prompt now names
   departments by `code` and `name` and describes them with the mandate, with no persona
   words.
   - The stage-1 **output parser** accepts both the new ids and legacy ids, via
     `normalizeDepartmentId`, for robustness.
3. Seeded handoff rules, system automations and activity kinds get the new ids from the
   inventory. **Stored ids of system automations are migrated by ZC-03.** The API also
   aliases a legacy automation id on lookup, for one version.
4. Data-dir subpaths:
   - `herald/` → `comms/`, `maestro/` → `release/`.
   - The `data-dir.ts` helpers fall back to the legacy dir when the new one is missing.
5. Log messages and comments must not contain persona words (the I-6 grep includes
   comments).
6. `docs-sync`: one manifest row per renamed module. Move the `docs/api/<module>.md` files
   and update the wording.

**Verification:**
- `tsc -p apps/api`, exit 0.
- `pnpm api:test`, compared with the baseline.
- `health.e2e` is the DI oracle: it must be green (DI cycles via ModuleRef / lazy import
  stay as they are).
- Boot the dev API against a **copy** of the real data (`ZIBBY_DATA_DIR=<scratch copy>`,
  unmigrated) and check that
  `curl -s localhost:3333/api/departments | jq length` is 11. This proves read tolerance.

**Commit:** `refactor(api)!: subsystem modules → departments, persona modules → functional names`

## ZC-03 — Migration script + fixture migration (parallel with ZC-02)

**Paths:**
- `tools/migrate/zibbycorp-departments.mjs` and its test
  `tools/migrate/zibbycorp-departments.test.mjs` (vitest, temp dirs).
- `apps/api/data-test/**`, **only** via the script.
- `docs/plans/zibbycorp/migration-dry-run.md`.

**The script**

Usage: `node tools/migrate/zibbycorp-departments.mjs --data <dir> [--apply] [--report <file>]`

- **Dry-run by default.** It prints and optionally writes a per-file change report.
- `--apply` first copies the whole data dir to `<dir>/_backup-zibbycorp-<ISO>/`, then writes.
- It is idempotent: a second run reports 0 changes.
- It operates on:

  | Location | Change |
  |---|---|
  | `agents/*.md` and `pipelines/*.md` frontmatter | `ownerSubsystem:` → `department:`; values mapped. Body text is untouched. |
  | `gate-rules.json`, `handoff/**` (rules, fired, proposals, signal kinds) | Every subsystem id and `from`/`to`/target value is mapped. Fired fingerprints are kept. |
  | `approvals/**`, `tasks/**` | `ownerSubsystem`, `{kind:"subsystem"}` targets |
  | `automations/**` and `system-config.json` | Automation ids per the inventory (`sentinel-scan`→`security-scan`, …). The file is renamed if the id is in the filename. |
  | `subsystem-seen.json` | Renamed to `department-seen.json`, keys mapped |
  | `herald/`, `maestro/` | Moved to `comms/`, `release/` |
  | `vault/**` | MOC notes `subsystem-<old>-moc.md` → `department-<new>-moc.md`. **Every `[[subsystem-<old>-moc]]` wikilink in the vault is rewritten.** `subsystem:` frontmatter → `department:`. Titles "Forge", … in those MOCs → the department name. |
  | `activity/**` (append-only JSONL) | **Not rewritten** (history is immutable). Readers tolerate old ids (ZC-01). |
  | `chains/` (a leftover from the amputation) | Moved to `_purged/chains-<ISO>/`, reported |

- Unknown files are listed as "untouched" in the report. The script never deletes: the only
  removal is a move into `_purged`/`_backup`.

**Deliverables**

1. The script and its tests. The tests cover:
   - every row above;
   - idempotence;
   - backup creation;
   - dry-run not writing.
2. Run `--apply` on `apps/api/data-test` and commit the fixture diff **as a separate
   commit**: `chore(data-test): migrate fixture to departments`.
3. Copy the real `.zibby/data` to the scratchpad, run `--apply` there, and boot the API on
   the copy. The ZC-02 curl check must pass. Record the result.
4. Run a **dry-run** against the real `.zibby/data` with `--report
   docs/plans/zibbycorp/migration-dry-run.md`. Never `--apply` the real data (D-008).

**Verification:**
- `pnpm exec vitest run tools/migrate`.
- The API tests stay green on the migrated fixture.

**Commits:**
- `feat(tools): zibbycorp department migration script`
- the fixture commit above

## ZC-04 — Web rename

**Paths:**
- `apps/web/features/subsystems/**` → `apps/web/features/departments/**`.
- Every `apps/web` importer.
- `apps/web/i18n/messages/{cs,en}.json`.
- `apps/web/e2e/**` specs and page objects.
- DS `immersive` consumers that take subsystem props. **Rename the props only**; the
  immersive code itself is deleted in ZB-13.

**Deliverables**

1. Symbol renames. The hooks become:
   - `useDepartmentsQuery`, `useDepartmentRosterQuery`, `useMarkDepartmentSeenMutation`;
   - `useAgentDepartment` (was `useOwnerSubsystem`);
   - `departmentVisuals`, which **loses colour** and keeps glyph/code/name.
2. i18n:
   - Rename keys `Subsystem*` → `Department*`.
   - cs values: "Subsystém" → "Oddělení".
   - Persona display names → department names:
     - cs: "Vývoj", "Provoz a monitoring", "Bezpečnost", "Release management",
       "Řešení incidentů", "Výzkum a vývoj", "Komunikace", "QA a architektura",
       "Správa znalostí", "Finance", "Osobní kancelář";
     - en: per D-004.
3. Test ids: `SubsystemDrawerTestId` etc. → `Department…`. Update the e2e page objects.
4. Agent and pipeline forms: the "Owner subsystem" field becomes "Department", required,
   with the same validation.

**Invariants:** the screens look the same. This is a rename only; the visual change comes
in Part A.

**Verification:**
- `tsc -p apps/web`, exit 0.
- `pnpm web:test`.
- `CI=true pnpm e2e`, compared with the baseline, via `rtk proxy`.
